Business rules implemented
--------------------------
PP5.1  Asset Category + Asset Class + LoB Tag mandatory
PP5.2  One Opportunity per LoB per Prospect (hard block)
PP5.3  Duplicate detection (same Category+Class+LoB) → configurable WARN or BLOCK
PP5.4  Opportunity ID generated on creation (OPP-YYYY-NNNNNN)

PP6.1  Product Model Price (NDLP) check; cost override + advisory message when NDLP ≠ submitted
PP6.2  Rack rate quote: no approval required
PP6.3  Customised quote: pricing deviation (finance > cost) triggers approval workflow
PP6.4  Unapproved customised quote cannot be shared
PP6.5  Multiple quote versions per Opportunity; prior DRAFT/APPROVED versions superseded
PP6.6  Quote state machine: Draft → [PendingApproval] → Approved → Shared → Locked
        Post-lock edits blocked; unlock requires REQUEST_UNLOCK → APPROVE_UNLOCK
PP6.7  Appraisal category mandatory before lock

PP7.1  Application initiated from LOCKED quote; pre-filled from Prospect; APP-YYYY-NNNNNN
PP7.2  Document checklist enforcement (PHOTO+PAN for individual; PAN for commercial)
PP7.3  KYC document upload → DMS (T/B/L per ENV_INDICATOR); index stored per document
PP7.5  Application ID, KYC status, CAM status always visible at Prospect screen
PP7.7  Non-individual (commercial) lessee auto-advances to ELIGIBLE_FOR_APPLICATION
PP7.8  Modification blocked when: CAM in non-final state (LN3713) or active fraud (LN3785)
PP7.9  Modification delete-and-re-insert pattern documented in ApplicationService
PP7.10 Fraud screening (Hunter+Sherlock) async post-save; non-blocking; failures suppressed
PP7.11 CIBIL bureau request for individual lessees; non-2xx logged silently; non-blocking
       Post-save caution screening; hard error blocks second commit; logs for Central Team
PP7.12 Welcome email+SMS dispatched when eligible lease type reaches ELIGIBLE_FOR_APPLICATION

CAM    CAM initiation in parallel with KYC; NOT_STARTED→IN_PROGRESS→APPROVED/DECLINED
       Sanction ID and package tracked; visible on Prospect screen
